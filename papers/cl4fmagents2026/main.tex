\begin{abstract}
Adaptation should not imply deployment: a better controller can still be installed unreliably. We define an executor contract combining expected installation identity, invocation quiescence, stateless admission, authority revalidation, and resource-atomic publication. A prototype implements it for one runtime slot. In a forced held-reader schedule, atomic publication makes the candidate current while a predecessor invocation remains live; guarded replacement returns \texttt{Busy} and admits no old/new invocation overlap. Across six rejection cases tested per protocol, both preserve the predecessor installation. Hosted measurements quantify replacement costs, retries, skipped dispatches, and retained bytecode. A payload-shift simulation replays frozen gain proposals to separate task quality from installation correctness. Foundation-model adaptation, downstream command fencing, and physical safety remain unevaluated.
\end{abstract}

\section{The update is part of the execution contract}
\label{sec:position}
After a payload change, an agent revises a motor reflex. Its candidate passes isolated tests, but activation races an old invocation whose command arrives later. A stale recovery request may also replace a newer installation reusing the same program handle. These installation failures are independent of controller quality.

Voyager grows executable skills through environmental feedback \citep{wang2023voyager}. Physical control adds restricted authority, deadlines, and irreversible effects. Our thesis is \emph{adaptation should not imply deployment}: candidates acquire authority through a transition with testable identity, concurrency, state, and accounting rules.

Qin et al. govern capability versions through compatibility checks, staged evaluation, activation, and rollback \citep{qin2026governed}. LITHE swaps controller pointers at Spine-cycle boundaries, obtaining implicit quiescence \citep{lim2026lithe}; Kitsune supports state-preserving software updates \citep{hayden2014kitsune}. Action shielding \citep{alshiekh2018shielding} and Neural Simplex's runtime assurance and retraining \citep{phan2020neural} remain complementary: publication determines which installation may issue actions.

We contribute (1) an executor installation contract; (2) a nonblocking implementation for one exclusive slot with monotonic epochs; (3) a same-manager atomic-publication comparison measuring correctness and availability; and (4) a simulated adaptation replay separating tracking quality from installation correctness.

\section{A narrow transactional publication primitive}
\label{sec:semantics}
A bare-metal Rust research kernel supplies verified runtime programs, load authentication, capabilities, quotas, and immutable snapshots. We add one opt-in exclusive TIMER slot. Ordinary TIMER fanout remains outside its gate; exclusivity concerns this slot. \emph{Transactional} denotes software-authority publication, without atomic physical effects or persistent recovery.

An installation is identified by
\begin{equation}
 I=(h,e), \qquad e\in\{1,\ldots,2^{64}-1\},
\end{equation}
where $h$ is a program handle and $e$ increases at every successful replacement, including rollback. Replacement checks the expected full $I$, preventing a stale request from becoming current when the same handle is reinstalled (ABA). Epoch exhaustion rejects; bootstrap is separate.

Invocation and replacement share one atomic state: open, active, or transitioning. Invocation claims open$\rightarrow$active, holds its snapshot guard throughout execution, and drops it before reopening. Other entry attempts return \texttt{TransitionBusy} or \texttt{ExecutionBusy} and increment skip counters. Replacement tries open$\rightarrow$transitioning once; an active invocation causes immediate, unchanged \texttt{Busy} rejection.

The prototype admits only candidates with no verifier-reported runtime-map references (\texttt{Stateless}). Stateful replacement and validated state transfer are unsupported. This policy makes no claim about physical, device, or external state.

Once quiescent, replacement checks expected identity, ownership, retained authentication provenance, bootstrap authority ceiling, TIMER re-verification, conflicts, and quota. Replacement uses the resident entry's immutable decoded instructions and retained load-time metadata. The source artifact is not retained: it reruns verification and policy checks without reparsing the ELF or rechecking its signature. Fallible snapshot preparation precedes mutation; a final serialized emergency-stop check rejects stop state or lock contention unchanged. The immutable published object contains runtime and full identity. The manager commits an allocation-free admission delta $-\mathrm{cost}(A)+\mathrm{cost}(B)$, publishes once, and records the receipt before reopening. Invocations read the object; serialized manager operations cannot observe intermediate ledger or receipt state. Both programs retain resident-memory charges. Rollback conditionally reinstalls the resident predecessor with a fresh epoch.

\paragraph{Two invariants.}
Assume serialized manager operations, normal returns, and invocations that hold their slot guard throughout their body. \emph{Invocation exclusivity:} if replacement from $I_A$ to $I_B$ succeeds, no guarded invocation of $I_A$ overlaps one of $I_B$. Entry claims open$\rightarrow$active; replacement claims open$\rightarrow$transitioning on the same atomic state. These claims exclude one another. Replacement publishes $I_B$ while transitioning, rejects new entries until completion, and reopens only with $I_B$ current. An old reader drops its snapshot before reopening. A successful invocation linearizes at its open-to-active transition; replacement linearizes at the pointer swap of the complete installation object.

\emph{Returned-error preservation:} every replacement returning an error preserves the published installation, executable snapshot, and admission ledger. All rejecting checks and snapshot preparation precede mutation. Ledger commit validates before writing; after it succeeds, publication and receipt updates have no error return. Releasing an unsuccessful transition only reopens the gate. This proposition excludes diagnostic counters, panic/crash recovery, and physical effects.

Receipts and diagnostic guard observations carry installation identity; production dispatch and actuation audit do not yet propagate it downstream.

\section{Correctness and availability under matched updates}
\label{sec:evaluation}
\paragraph{Same-manager comparison.}
\textbf{Atomic publication} (AP) and \textbf{guarded replacement} (GR) share validation, expected identity, ownership, authority, re-verification, accounting, snapshot preparation, and receipts. AP bypasses only the invocation gate through a host diagnostic path absent from bare-metal builds. Both publish the same immutable identity/runtime object. AP retains the predecessor allocation and waits for old readers before returning, but B becomes visible during that wait. A B reader can therefore overlap an A reader. GR returns \texttt{Busy} while A is active; a later retry can publish B. Each fixture fixes its protocol until draining cleanup.

Hand-written map-free bytecode uses unsigned development loading, so authentication is not tested. Hosted callbacks hold real guards without privileged bytecode execution or actuation. The admission model assigns 1\,kHz hook frequency and 500\,ms/s CPU budget; unrelated reservations exercise that budget. Fixture charges are measured through manager attachments, not execution timing. A separate QEMU probe checks interpreter dispatch after A--B--A and stale-request rejection.

\paragraph{Fault schedules.}
Both protocols receive snapshot-preparation failure, over-budget, authority, stale-identity, retry, ABA, rollback, and concurrent-proposer schedules. Rejections preserve snapshot, identity, ledger, and receipt. One schedule retains A, starts replacement, and attempts a B invocation. AP exposes B before A drains; GR rejects until A drains. Overlap records carry identities captured by actual guards. Accounting is checked outside callbacks: taking the manager lock while AP waits for a reader would deadlock.

\paragraph{Installation-conditioned control replay.}
An eight-second host simulation integrates $m\dot v=u-v$ by 100\,$\mu$s Euler steps, with mass $1\rightarrow2$ at four seconds and reference alternating $\pm1$ each second. Control ticks every millisecond use $u=\mathrm{clip}(k(r-v),-4,4)$. A seed tuner, starting at $k=1$, doubles gain up to 16 when recent 250\,ms tracking RMSE exceeds 0.1, at 4.25, 4.5, 4.75, and 5 seconds. We freeze these proposals before replaying frozen control, AP, and GR.

Real manager installations and guards select the gain; host code computes control. Each invocation captures identity and error at entry and applies its command at completion, with zero-order hold between commands. Normal holds are 100\,$\mu$s; one predecessor invocation at 4.249\,s lasts 2\,ms. Completion precedes update attempts, then control ticks. Each proposal has the same primary and $+1$\,ms attempt; AP can expose B while A remains held, whereas GR must retry. RMSE includes skipped ticks. Paired synchronous utility probes compare candidate and predecessor gains from the same activation state over 250\,ms; they do not estimate a learning algorithm's performance.

\section{Scope and implications}
\label{sec:limits}
We do not claim atomic pointer exchange or quiescence as new in isolation. The contribution is an agent-facing executor contract combining quiescence with expected installation identity, authority revalidation, explicit state admissibility, resource-atomic accounting, and observable availability outcomes.

Quiescence serializes invocations and trades availability for rejection; acceptability depends on the controller and schedule. Retaining predecessors costs memory; stateless admission excludes useful updates. Middleware could enforce this contract. AP is a manager ablation, not LITHE, whose single loop supplies cycle-boundary quiescence.



The contract ends at the guarded invocation. Commands can outlive their installation; physical motion cannot be rolled back. Queue fencing requires propagated identity and a stale-command rejection point. Controller stability, state transfer, persistent recovery, hardware-stop timing, and foundation-model continual learning require separate experiments. The replay illustrates two evaluation axes, without a robot or privileged controller execution: adaptation should not imply deployment.
