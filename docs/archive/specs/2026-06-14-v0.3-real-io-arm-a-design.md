## 1. Goal

Make one real sense path and one real actuate path provably work on hardware, with every
actuation passing through a reference monitor (ARM-A) that clamps it into a safe envelope.

Spec 1 delivers:
- **G — GPIO sense path** proven and made precise (per-`(chip,pin,edge)` routing + a test that
  drives it + a measured full-loop latency).
- **A — ARM-A core**: a pure actuation-decision module (clamp + absolute-limit + slew-rate-limit)
  enforced on every actuation entry point (`bpf_pwm_write`, `bpf_gpio_write`, `sys_pwm_write`).
- **C — reflex bench**: a verified BPF program reacts to a real GPIO edge and drives a real PWM
  through ARM-A; edge→PWM latency and monitor overhead measured on Pi5.

**Gate unlocked:** Patent 3 (multi-modal HW attach, profile-bounded) enablement.

## 2. Reality delta (what the code actually does today)

The roadmap assumed GPIO→BPF was "scaffolded, not wired." Inspection shows the **sense loop already
runs end-to-end in code**:

- `sys_bpf` `BPF_PROG_ATTACH` (`kernel/src/syscall/bpf.rs:290-331`) reads `pin = attr.key`,
  `edge = attr.value`, calls `Rp1Gpio::configure_input(pin)` then `enable_interrupt(pin, rising, falling)`.
- An edge raises an IRQ → `handle_irq` (`kernel/src/arch/aarch64/interrupts.rs:106`) →
  `rpi5::gpio::handle_interrupt()` (`gpio.rs:328`).
- `handle_interrupt` scans pins, reads edge + value, builds a fully-populated `GpioEvent`
  (`timestamp/chip_id/line/edge/value`), wraps it in a `BpfContext`, calls
  `get_hook_programs(ATTACH_TYPE_GPIO)`, and runs each via `BpfManager::execute_program`.

So the remaining GPIO gaps are narrow:

- **G1 — no per-pin routing.** `BpfManager::attachments: BTreeMap<u32, Vec<u32>>` keys on attach
  *type* only (`ATTACH_TYPE_GPIO = 2`). `handle_interrupt` runs *every* GPIO program on *any* pin
  edge. Two sensors cross-fire; rising and falling cannot be distinguished per program.
- **G2 — nothing exercises the IRQ path.** `kernel/crates/kernel_bpf/tests/gpio_integration.rs`
  constructs `GpioEvent`s by hand and uses stub helpers; the arm→edge→dispatch path is unproven.
- **G3 — full-loop latency unmeasured.** The 211 ns figure is interrupt→BPF *entry*; edge→PWM-out
  was never measured.

The actuation side is genuinely net-new: `bpf_pwm_write` (`kernel/src/bpf/helpers.rs:248`),
`bpf_gpio_write` (`helpers.rs:109`), and `sys_pwm_write` (`kernel/src/syscall/pwm.rs:34`) write
straight to RP1 MMIO with only a channel-range check. **ARM-A is the primary deliverable.**

## 3. Architecture

Pure decision core in the host-testable `kernel_bpf` crate; a thin enforcement seam in the kernel
binary crate maps decisions onto MMIO. The pure core carries no MMIO, so the safety invariant is
proven by host `cargo test` (unit + property), not only on hardware.

```
kernel_bpf::actuation                       (PURE, no_std, host-testable)
  ├ ActuationKind, ChannelId, ActuationRequest
  ├ Envelope            (built from PhysicalProfile assoc consts)
  ├ ChannelState        (last_output, last_update_ns, safe_hold)
  ├ Decision            (Allow | Clamp | Safe | Reject)
  └ Monitor<P>::decide(&mut self, req, now_ns) -> Decision

kernel/src/actuation.rs                      (HW seam, binary crate)
  ├ static ACTUATION_MONITOR: Mutex<Monitor<ActiveProfile>>
  ├ guard_pwm(chip, channel, duty) -> i64    (the ONLY writer of PWM duty)
  └ guard_gpio(pin, level) -> i64            (the ONLY writer of GPIO output level)

routing (G1) in kernel/src/bpf/mod.rs
  └ per-(chip,pin,edge) GPIO attachment map + pin-filtered dispatch
```

Profile constants mirror the existing pattern: tight on `EmbeddedProfile`, unbounded no-ops on
`CloudProfile` (exactly how `WCET_CYCLE_BUDGET` / utilization disable themselves off-target).

## 4. Components and interfaces

### 4.1 `kernel_bpf::actuation` (new module)

```rust
/// What kind of actuator a request targets. Determines the safe state.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ActuationKind {
    /// PWM duty cycle, percent 0..=100.
    PwmDuty,
    /// GPIO output level, 0 or 1.
    GpioLevel,
}

/// Identifies a physical output channel.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct ChannelId {
    pub kind: ActuationKind,
    /// PWM: controller id (0|1). GPIO: 0.
    pub chip: u8,
    /// PWM: channel (1|2). GPIO: pin (0..=27).
    pub channel: u8,
}

/// A requested actuation, before the monitor decides.
#[derive(Debug, Clone, Copy)]
pub struct ActuationRequest {
    pub ch: ChannelId,
    pub value: u32,
}

/// The safety envelope for a channel. In Spec 1 every known channel of a given
/// kind shares a profile-derived envelope; Spec 2 replaces this with a
/// per-channel RO map.
#[derive(Debug, Clone, Copy)]
pub struct Envelope {
    pub min: u32,
    pub max: u32,
    /// Max change in output per `window_ns`. 0 disables slew limiting.
    pub max_step: u32,
    /// Rate-limit window in nanoseconds. 0 disables slew limiting.
    pub window_ns: u64,
}

/// Why a request was structurally refused (distinct from a policy-safe outcome).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum RejectReason {
    /// No envelope exists for this channel (deny-by-default).
    UnknownChannel,
}

/// The monitor's decision. Four distinguishable outcomes so that audit logs,
/// authority decisions, and incident replay (Spec 2) can tell apart a normal
/// pass, a bounded clamp, a policy-enforced safe output, and an invalid request.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Decision {
    /// Request was inside the envelope; apply `value` unchanged.
    Allow(u32),
    /// Request was clamped (magnitude and/or slew); apply the bounded value.
    Clamp(u32),
    /// Policy forced the channel to its safe value (safe-hold / e-stop / veto).
    Safe(u32),
    /// Request was structurally invalid; caller drives the universal safe (0).
    Reject(RejectReason),
}

/// Per-channel mutable state. Modeled explicitly: slew-rate limiting,
/// auditability, and Spec 2 extensions all depend on it.
#[derive(Debug, Clone, Copy)]
struct ChannelState {
    last_output: u32,
    last_update_ns: u64,
    /// When true, every request resolves to `Safe(min)`. Set by `hold_safe`,
    /// cleared by `release`. Spec 2's e-stop latch and authority veto drive this.
    safe_hold: bool,
}
```

```rust
pub struct Monitor<P: PhysicalProfile> { /* channel states + profile marker */ }

impl<P: PhysicalProfile> Monitor<P> {
    pub const fn new() -> Self;

    /// Decide the fate of one actuation request.
    ///
    /// `now_ns` MUST be monotonically non-decreasing across calls for a channel;
    /// slew-rate semantics are otherwise undefined. The implementation is
    /// defensive — `elapsed = now_ns.saturating_sub(last_update_ns)` collapses any
    /// backward step to 0, which applies the strictest slew limit rather than
    /// silently widening it.
    pub fn decide(&mut self, req: ActuationRequest, now_ns: u64) -> Decision;

    /// Latch a channel into safe-hold; subsequent `decide` calls return `Safe(min)`.
    /// (Spec 1 defines + tests this; Spec 2 wires the production callers.)
    pub fn hold_safe(&mut self, ch: ChannelId);

    /// Release a safe-hold.
    pub fn release(&mut self, ch: ChannelId);

    /// The envelope for a channel, or `None` if unknown (deny-by-default).
    fn envelope(&self, ch: ChannelId) -> Option<Envelope>;
}
```

**`decide` algorithm:**

1. `envelope(ch)` is `None` → `Reject(UnknownChannel)`.
2. `safe_hold` set → commit `min`, return `Safe(min)`.
3. Magnitude clamp: `v = value.clamp(min, max)`; record whether changed.
4. Slew clamp (only if `window_ns > 0` and `elapsed < window_ns`):
   bound `v` into `[last_output − max_step, last_output + max_step]` re-intersected with
   `[min, max]`; record whether changed. (`saturating_*` throughout.)
5. Commit `(v, now_ns)`; return `Clamp(v)` if step 3 or 4 changed the value, else `Allow(v)`.

**Known channels (Spec 1):** PWM `chip ∈ {0,1}`, `channel ∈ {1,2}`; GPIO `chip = 0`, `pin ∈ 0..=27`.
Anything else → `UnknownChannel`. The envelope is kind-specific, built by
`Envelope::from_profile::<P>(kind)`:

- **`PwmDuty`** → `min = 0`, `max = ACT_DUTY_MAX`, `max_step = ACT_DUTY_MAX_STEP`,
  `window_ns = ACT_RATE_WINDOW_NS` (the profile constants).
- **`GpioLevel`** → `min = 0`, `max = 1`, `max_step = 1`, `window_ns = 0` (slew not meaningful on a
  binary line). For GPIO the monitor's role is the magnitude clamp to `{0,1}` plus the `safe_hold`
  gate — relevant because GPIO outputs include H-bridge direction pins, where forcing a safe level
  on e-stop (Spec 2) matters.

Per-channel envelopes (distinct limits per motor/servo) are Spec 2 (RO map).

**Safe value:** `envelope.min`. For the v1.0 differential-drive rover, every driven channel has
`min = 0` = stopped = safe. Channels whose safe state ≠ `min` are out of Spec-1 scope (a later
`safe_state` field on `Envelope` covers them with no structural change). Unknown channel → caller
writes `0` (universally safe for PWM duty and GPIO level), justified by deny-by-default: an unknown
channel must not be wired to a live actuator.

### 4.2 `PhysicalProfile` additions (`kernel_bpf/src/profile/mod.rs`)

Add three associated constants to the `PhysicalProfile` trait, set in both impls:

| Const | `EmbeddedProfile` | `CloudProfile` | Meaning |
|---|---|---|---|
| `ACT_DUTY_MAX: u32` | `90` | `u32::MAX` | absolute duty ceiling (%) |
| `ACT_DUTY_MAX_STEP: u32` | `20` | `u32::MAX` | max duty change per window |
| `ACT_RATE_WINDOW_NS: u64` | `1_000_000` (1 ms = control period) | `0` (disabled) | slew window |

`Envelope::from_profile::<P>(kind)` builds the Spec-1 envelope: `PwmDuty` reads these constants;
`GpioLevel` is the fixed `{0,1,1,0}` envelope. On cloud the constants make PWM clamp/slew no-ops,
matching how WCET admission disables itself there.

### 4.3 HW seam (`kernel/src/actuation.rs`, new)

```rust
pub static ACTUATION_MONITOR: Mutex<Monitor<ActiveProfile>> = Mutex::new(Monitor::new());

/// Route a PWM-duty request through ARM-A and apply the decision to RP1 MMIO.
/// Returns 0 when motion proceeds (Allow/Clamp), -1 when policy intervened or the
/// request was invalid (Safe/Reject). The only *monitored* writer of PWM duty.
pub fn guard_pwm(chip: u8, channel: u8, duty: u32) -> i64;

/// Same contract for a GPIO output level. The only *monitored* writer of GPIO output.
pub fn guard_gpio(pin: u8, level: u32) -> i64;
```

The seam governs **actuation magnitude** — PWM duty and GPIO output level. PWM frequency/range and
channel enable/disable (`sys_pwm_config`, `sys_pwm_enable`, the `enable`/`disable` in `pwm.rs`) are
privileged setup, not magnitude, and stay outside ARM-A in Spec 1.

Decision → (MMIO value, return code):

| Decision | MMIO write | return |
|---|---|---|
| `Allow(v)` | `v` | `0` |
| `Clamp(v)` | `v` | `0` |
| `Safe(v)` | `v` (= min) | `-1` |
| `Reject(_)` | `0` | `-1` |

**Enforcement edits** (every *normal* actuation-magnitude path routes through the seam):

- `kernel/src/bpf/helpers.rs` — `bpf_pwm_write` → `guard_pwm`; `bpf_gpio_write` → `guard_gpio`.
- `kernel/src/syscall/pwm.rs` — `sys_pwm_write` → `guard_pwm`.
- `bpf_motor_emergency_stop` is left as-is: it writes the safe value (0) directly, a deliberate
  defense-in-depth bypass of the monitor (the emergency path must not depend on monitor state). Spec 2
  reframes it as the latch driver via `hold_safe`. This is the one sanctioned direct duty writer.

### 4.4 GPIO per-`(chip,pin,edge)` routing (G1)

- `BpfManager` gains a GPIO route table keyed on `(chip: u8, pin: u8, edge: GpioEdge)` → `Vec<prog_id>`
  (alongside the existing type-keyed `attachments`, which other attach types keep using).
- `sys_bpf` `BPF_PROG_ATTACH` for `ATTACH_TYPE_GPIO`: in addition to arming the pin (already present),
  record the route `(chip, pin, edge)` for `prog_id`. `pin = attr.key`, `edge = attr.value`; `chip = 0`
  (RP1 bank 0 — the only GPIO bank wired in Spec 1). `chip` is kept in the key for forward-compat
  (second bank / Shrike GPIO later) without a redesign.
- `handle_interrupt`: it already knows the firing `(pin, edge)`; replace the type-wide
  `get_hook_programs(ATTACH_TYPE_GPIO)` call with a pin+edge-filtered lookup so only matching
  programs run. The lookup/selection is a pure function on the route table → host-testable without MMIO.
- Admission (`AdmissionLedger`) and detach are updated to match the route granularity.

## 5. Data flow

```
SENSE  edge ─IRQ→ handle_irq ─→ handle_interrupt
            └ build GpioEvent ─→ route by (chip,pin,edge) ─→ matching BPF program runs

ACT    BPF: bpf_pwm_write(chip, ch, duty)
            └ guard_pwm ─→ ACTUATION_MONITOR.decide(req, ktime_ns)
                              ├ Allow(v)/Clamp(v) → set_duty_cycle(ch, v); ret 0
                              ├ Safe(v)           → set_duty_cycle(ch, v=min); ret -1
                              └ Reject(_)         → set_duty_cycle(ch, 0);    ret -1

REFLEX (bench) bumper edge → routed reflex program → bpf_pwm_write(0) → guard_pwm → motor low
```

## 6. Error handling & fail-safe

- **Clamp, don't reject, for in-range-able requests.** Magnitude and slew violations clamp into the
  envelope and let bounded motion continue — the robot stays controllable. `Reject` is reserved for
  structurally invalid requests (unknown channel).
- **Reject and Safe both yield an in-envelope output**, never a runaway: `Reject` writes `0`, `Safe`
  writes `min`. They remain distinct *outcomes* (and, in Spec 2, distinct audit events): `Reject` =
  bad input, `Safe` = policy intervention.
- **Deny-by-default:** a channel with no envelope is unknown → `Reject` → safe.
- **Monotonic-time defense:** backward `now_ns` collapses `elapsed` to 0 (strictest slew), never
  widens the allowance.

## 7. Testing & acceptance

### Host (`cargo test` in `kernel_bpf`, CI-runnable)
- **Property test (proptest)** — the core ARM-A invariant. For a known channel with `safe_hold = false`,
  over randomly generated `(value, prior ChannelState, now_ns)` with `now_ns ≥ prior.last_update_ns`:
  the applied output is always within `[min, max]`, and when `elapsed < window_ns` the step from
  `prior.last_output` is `≤ max_step`. This is the direct evidence for the "0 escapes" claim.
- **Fixed corpora (regression anchors):** a clamp corpus, a slew corpus, and ≥1000 enumerated invalid
  requests → 0 escapes.
- **Outcome-distinction tests:** each of `Allow / Clamp / Safe / Reject` is produced by a constructed
  case (`Safe` via `hold_safe`; `Reject` via an unknown channel).
- **Routing selection tests:** the pure `(chip,pin,edge)` route lookup returns exactly the matching
  programs (rising vs falling on one pin are independent; two pins do not cross-fire).

### On-device (Raspberry Pi 5)
- **Reflex integration self-test (closes G2):** load + verify + attach a GPIO-edge reflex program that
  calls `bpf_pwm_write(0, 1, 0)`; drive the input edge; serial log confirms the program ran and PWM
  went low.
- **Edge→PWM-low latency (closes G3):** CNTVCT-timed full loop (extends the existing 211 ns interrupt
  harness to include the actuation write). Target **< 500 ns**, fallback claim **< 1 µs** (roadmap DP2).
- **ARM-A overhead:** `set_duty_cycle` cycles with vs without the monitor. Target **< 5 µs** added
  (expect tens of ns).

### QEMU smoke (regression guard)
- Kernel boots and loads/verifies/admits a program with ARM-A compiled in. (QEMU has no RP1 model, so
  GPIO-edge and PWM-MMIO paths are Pi5-only; this guards the build + non-HW paths.)

### Acceptance criteria for Spec 1
1. Property test + corpora pass: **0 escapes** on host.
2. All four `Decision` outcomes and the routing selection are unit-covered.
3. On Pi5: reflex loop proven (G2), edge→PWM latency reported (G3), monitor overhead reported.
4. No actuation-magnitude path writes duty/level MMIO except through `guard_pwm` / `guard_gpio` — the
   sole sanctioned exception being `bpf_motor_emergency_stop` writing the safe value (0) directly.

## 8. Out of scope (Spec 2 seams — pure extension, no rework)

- **Kernel e-stop latch** → drives `Monitor::hold_safe` on all channels; produces `Safe`.
- **Authority lattice** (`Safety > Operator > Mission > Learned`) → an authority field on the request;
  a veto resolves to `Safe`.
- **Audit ring** → emit one event per `Decision` (the four outcomes are already distinct).
- **Per-channel RO envelope map** + **map-write-permission lattice** → replaces `Envelope::from_profile`
  with a verifier-RO map lookup; behaviors cannot rewrite their own limits.
