# axiomos v0.5: bounded runtime evolution

## Authority, baseline and development gate

This is the canonical v0.5 product and engineering contract, accepted by the
operator on 2026-09-12, with development sequencing revised by the operator on
2026-09-15. The complete M0–M7 scope below is the target. Software implementation
and host/model testing now precede the final hardware campaign; software
completion alone is not a v0.5 release. The [older engineering draft](v0.5-runtime-evolution-engineering-draft-v2.md)
is preserved as historical input and does not add requirements to this contract.

The P0–P5 ordering comes from the
[architecture convergence report](../../reviews/architecture/architecture-convergence-report.md),
originally `output/architecture-convergence-report.md:739`, following session
`01a0916d-f332-7741-b184-fbd60830cb10`. The requested prerequisite baseline
`55221ff` is already an ancestor of `66f6585`, the runtime branch's original head.
It includes the subsequent stack provenance fixes `97bdd2f` and `d87e812`.
The starting worktree fast-forwards to the common
[v0.5/FPGA development baseline](../../reviews/releases/2026-09-12-v0.5-fpga-baseline/README.md),
`05e2b25` (`baseline/v0.5-fpga-start`). Its two additional commits integrate HIL
history and reorganize documentation; kernel, firmware, userspace and scripts
are unchanged from `66f6585`. Work uses the `volngithub` remote and
`feat/v0.5-runtime`; the parallel FPGA branch is `feat/fpga-bringup`.
Review each series independently; never merge the research branch wholesale.

The working objective is to complete the v0.5 software implementation and
host/model tests on `feat/v0.5-runtime`, including the required M1 software
prerequisites and M2–M6. Continue software work without pausing for routine
hardware measurements. Keep physical actuation disabled during development;
document unmeasured adapter and timing assumptions as provisional rather than
inventing qualification evidence.

The operator's 2026-09-15 decision supersedes the earlier requirement to complete
the [hardware-first plan](v04-hardware-first.md) before broad implementation.
Its electrical, recovery and operational safety checks remain mandatory in the
final hardware phase. After software completion, perform the deferred M1
electronics qualification and M7 runtime-evolution campaign, including their
functional/fault checks, pilots and 24-hour soaks. Follow the staged bench
checks before enabling hardware actuation. Motors and motor power remain
disconnected; powered motor and assembled-car qualification are later gates.

At this baseline, operational FPGA, production stop/rearm and soak acceptance
remain open. The newer retained diagnostic evidence completes 10,000 paired
safe-LOW monitor measurements and 1,000 PWM corpus requests. Physical GPIO reflex
still misses the legacy latency target. GPIO e-stop diagnostics automatically
rearm and do not prove production latching. Each result belongs to its recorded
image; none qualifies the new controller, handoff protocol or FPGA output path.
The historical hardware plan's earlier incomplete populations are not the latest
campaign status; use the dated baseline evidence above.

The input is capped at the same 2 MiB range, with one byte in flight, a checked
whole-transfer deadline, finite total polls and a separate same-tick poll cap.
Runtime transfers keep their original total poll cap. Host models exercise
stale/missing CONFIG, every partial byte timeout, late pin release and a
46,408-byte synthetic transfer including a frozen-clock case. These do not
establish physical pin timing or qualify that fixture as an FPGA artifact.
`R04Platform` now uses this stream and latched READY path. The same SPI owner
implements bounded PWR/EN/CS startup and runtime rebinding: reset stays asserted,
PWR/EN remain low for the declared interval, CS is low before power-on, and the
startup pulse precedes exact-image streaming. Input validation enforces the
[SLG47910 configuration guide](https://www.renesas.com/en/document/mah/forgefpga-configuration-guide)
Rev.2.5 section 8.1 startup minima, the
[datasheet](https://www.renesas.com/en/document/dst/slg47910-datasheet)
reset minimum and the 16 MHz configuration-clock ceiling using the actual
peripheral-clock ratio. These minima are not a qualified board timing profile.

Runtime entry consumes the CONFIG latch, waits a separately declared Hi-Z
interval, resets/reconfigures SPI while runtime reset remains asserted, releases
that reset pin and waits the declared settling interval. A separate functional
status read must return READY with no previous command or sequence. This does
not release e-stop or authorize motion. Startup and runtime entry each check an
absolute deadline including initial control-pin I/O, checked arithmetic and a
frozen-clock poll cap. Failures inhibit the bus and restore power/reset safe;
SPI0 reset recovery uses bounded hardware-reset polls, with no command retry.
UART0 and SPI0 share RESETS sequentially on the sole MCU main context; no IRQ
or other core may modify it. Host tests cover ordering, invalid timing/rates,
clock and pin failures, consumed completion and recovery boundaries. Target
compilation covers the concrete PAC/HAL ownership. The qualified image and
single timing profile remain `None`, and the feature guard still rejects an
operational build. Production session/rearm integration and physical timing
qualification remain open; no example timing is promoted.

The MCU FPGA source now uses a checked, immutable `BitstreamImage` inside the
existing lifecycle module. It validates the reserved flash range, exact byte
length and SHA-256 before retaining a borrowed source; later streaming can
request only that same offset/length. Verification reuses the repository's
software `sha2` implementation with no heap allocation and a 2 MiB input cap.
The R0.4 target checks its selected manifest before constructing the mapped
flash view and clears that reference on every safe reset or verification
attempt. The disabled default selects no image and reads no storage. A future
selected image must occupy the exact raw reserved range; an offset into the
factory filesystem is not interchangeable. Host tests cover the known digest,
every digest/source-byte mutation, malformed ranges and lengths, exact binding
and borrowed storage. These do not qualify flash provisioning or throughput.

The MCU runtime now owns SPI0 and its GPIO0/1/2/3 pins through a bounded
mode-0 transaction adapter, used by `R04Platform` for the complete 12-byte
command and separate two-byte post-commit status read. It rejects stale FIFO
state and overruns, waits for TX FIFO and shift-register completion, and
checks elapsed time through the final CS edge. One byte in flight bounds RX
occupancy; a 65,536-poll cap also terminates a frozen timer. CS setup, hold
and high intervals require explicit candidate timings, including a timer-tick
quantization guard. Host models cover byte-offset RX timeouts/overruns, TX
backpressure, final BSY, clock regression/exhaustion and late completion.
These are software checks, not measured SPI timing or remote-output evidence.
The constructor only resets SPI0 with SSE disabled. Configuration streaming
and the READY/runtime transition are implemented as described above. Qualified
timing/artifact selection and production session/rearm integration remain open;
the feature guard and artifact `None` remain in place. The adapter uses the existing clock owner, replacing a raw
TIMER pointer; no dependency or wire-format change is required.

The final hardware phase starts with powered-off continuity/voltage checks,
then configuration/READY/SPI handoff and clock measurements on the unloaded
bench. The real adapter, post-route hold/pulse and asynchronous interface
qualification, physical reset/drain, functional/fault campaign, one-hour pilot
and 24-hour soak remain open. On 2026-09-13 the operator confirmed V1.0/R0.4,
the installed firmware payload matched the vendor Shrike-Lite UF2, and a
same-image restoration through software-entered RP2040 ROM loading passed.
Subsequently, the operator established firmware-independent ROM entry by
holding BOOT and pressing/releasing RST with USB connected. The same vendor
image was restored through that physical entry; firmware identity and the
complete 4 MiB flash hash again matched the original backup. The
[retained recovery record](https://github.com/volnlabs/axiomos/blob/65f2de437542cdb382e359ed1df0d3644af7e14e/docs/plans/active/shrike-fpga-bench.md)
marks that exact artifact and BOOT + RST procedure ready on the identified
board. Three cold BOOT-held reconnection attempts failed; their cause remains
unknown. Cold-entry success is not claimed, and `fpga-runtime` stays disabled.
Electrical and FPGA qualification remain open for the final hardware phase;
they do not block M2–M6 software implementation and host/model tests. Do not
repeat bitstream generation merely because the older baseline record still
lists it as missing.

## 1. Product definition and decisions

An operator can upload a signed controller to a running Pi5, prepare it while
the active controller runs, transfer control through a confirmed safe-output
interval, manually return to the previous artifact, and inspect the audit trail.
Every activation and rollback starts with fresh private state and bounded memory.

| Decision | v0.5 contract |
|---|---|
| Control rate | One CPU0 executor at 100 Hz with absolute 10 ms deadlines |
| Replacement | A deliberate safe-output pause; confirm the sink is safe before publication |
| State | Fresh, zero-initialized private state on every activation and rollback |
| Rollback | Explicitly select the retained previous artifact; issue a new installation generation |
| Retention | One active artifact, one previous artifact, one transient candidate |
| Recorder | Bounded RAM window, export and explicit loss accounting |
| Hardware | Real Pi5/RP2040/programmed-FPGA electronics; motors and chassis deferred |

“No missed behavior cycles during replacement” is replaced by continuous service
of 100 Hz releases selecting the controller or trusted safe-output mode. Record
safe handoff cycles. “Activation takes less than one cycle” applies only to
publication and entry after preparation and sink-safe acknowledgement. Measure
upload, authentication, verification, preparation and physical handoff separately.

General state migration, frozen-state restoration, deterministic replay,
crash-persistent recording, automatic rollback, SMP controller execution and
Linux integration are outside v0.5.

## 2. Reuse the implementation; close the actual gaps

| Area | Existing implementation and required disposition |
|---|---|
| Lifetime | Extend generational handles, quotas, map execution leases, unload and owner cleanup; no second registry or reclamation framework |
| Dispatch | Preserve immutable runtimes, hook snapshots and per-CPU execution storage; add one exclusive managed role outside ordinary fanout |
| Atomic pairs | Pi fixes and the MCU's single `FpgaLifecycle` pair sink are integrated; real-adapter and physical qualification remain open |
| Freshness/stops | Reuse corrected watchdog, pending-command and FPGA models; qualify the real adapter and acknowledged handoff |
| ELF loading | PWM rejection is preserved; manager now rejects multiple entries/maps and the parser rejects unsupported or ambiguous relocation composition before publication |
| Authority | Full signer identity and the narrow `BEHAVIOR_ADMIN` bit exist; provision the installer and connect managed administration to kernel-owned deployment lifetime |
| Scheduling | Absolute AArch64 releases and worker preparation now exist; connect managed invocation and preserve bounded management calls. Legacy AArch64 syscall dispatch remains IRQ-masked and outside the qualified workload |
| Audit | Extend monitor-local decisions with lifecycle identity, actual request outcomes, bounded export and loss reporting |
| Tooling | Replace boot-file-only signed loading and simulated/local-copy deployment with genuine post-boot upload |

The ELF parser handles supported map and call relocations. The legacy manager
rejects ELF map declarations because it does not install their bindings.
Authentication already returns provenance; current manager entries discard it.
`SYS_BPF` checks command capabilities before a global full-`BpfAttr` size check;
managed command authorization and versioned decoding must precede that legacy
size check while preserving legacy behavior for legacy commands.

## 3. Identity, ownership, private state and resources

| Object | Contents and lifetime |
|---|---|
| `BehaviorArtifact` | Immutable signed identity, normalized code, verifier result, admission cost and binding contract |
| `BehaviorInstance` | Artifact reference, newly allocated private state and captured runtime bindings |
| `Installation` | Instance, kernel-issued generation, control-slot authority and activation receipt |

Artifact identity includes logical behavior ID, signer revision, digests of the
canonical signed bundle and executable payload, full signer fingerprint,
supported helper/context versions and state declaration. Artifact identity and
installation generation are distinct: A→B→A never reuses A's former generation.

The manager owns accepted managed artifacts and installations independently of
loader PID. Incomplete uploads remain process-owned and are canceled on exit.
Once a preparation request is accepted into kernel ownership, loader exit neither
removes the controller nor silently cancels the accepted operation. Use explicit
ownership types where managed ownership meets existing accounting and cleanup;
do not introduce ambiguous PID sentinels.

Private state is absent or one zero-initialized ARRAY map with at most 16 KiB
payload. Reuse `MapRuntime`, its lease and existing array storage. Managed bundles
use fixed local bindings, without general ELF map relocation:

- Handle 0: the existing read-only envelope view, when declared.
- Handle 1: the private array, when declared.
- Reject other handles, shared writable maps, pinning, external mutation and
  nonzero initializers.

Verify with the exact local sizes, permissions and generations. Fresh instances
must match the retained binding contract, allowing verified code sharing without
instruction patching or weaker verification. Previous artifacts retain no old
mutable controller state.

Use existing embedded program/map budgets without increasing them. The initial
managed bounds are one control slot, at most three distinct artifacts, one
incomplete upload of at most 256 KiB, one accepted management operation, at most
two state instances, one preallocated retirement batch and four terminal
receipts. There is no append-only operation history.

The retirement batch must hold both the displaced instance and an evicted
previous artifact so that no last substantial reference is freed by the timer.
Charge upload storage, verifier workspace, code, private maps, staged and retired
objects until actual release; shared code is charged once. Reject preparation
with busy/capacity errors while retirement capacity is unavailable. Never reclaim
through a live reader or force a reader wait in control.

Preparation requires checked allocation and bounded verifier byte storage.
A state-count cap alone is insufficient: reachable infallible allocation and
clone paths need fallible preparation equivalents. Exhaustion rejects the
candidate without unwinding into the active controller.

### Lifecycle and manual rollback

```text
upload -> authenticate/verify artifact -> resident candidate
       -> prepare/admit fresh instance -> request handoff
       -> old invocation completes -> trusted safe mode -> sink confirms zero
       -> publish installation -> execute new controller

displaced artifact -> previous
displaced instance + evicted previous artifact -> retirement batch -> worker release
previous artifact -> fresh instance -> same handoff -> new installation generation
```

Preparation failure preserves active identity, private state, previous artifact
and active admission charge. Entering handoff deliberately inhibits motion;
subsequent failure may leave the old installation current but stopped. Publication
has one authoritative commit point, no old invocation crosses it, and no fallible
work follows its first mutation. Retiring an active installation requires explicit
deactivation through the same safe boundary; ordinary stop does not unload code.
Expired handles, stale expected generations and counter exhaustion reject
explicitly. Physical actions are never rolled back.

Rollback supplies the expected current generation and exact retained artifact.
It allocates zeroed state, reuses verified code/bindings, rechecks admission and
authority, follows the same safe handoff and increments generation. The displaced
active artifact becomes previous, allowing another explicit rollback with fresh
state. No fault automatically selects previous code; no persistent security
anti-rollback policy is claimed.

## 4. Execution, handoff and failures

### Absolute 100 Hz executor

Reuse the physical timer with `next_deadline += period`. Number scheduled releases,
account for lateness and missed releases, advance past missed deadlines without
catch-up bursts, and invoke at most one managed controller per release. Freeze
one trusted sensor snapshot throughout an invocation.

Pass a new versioned managed payload through the existing context mechanism:
cycle identity, scheduled/actual timestamps, sensor value, timestamp and validity.
Existing IIO/context layouts remain unchanged. Managed control never runs through
ordinary TIMER/IIO fanout. Disable generic TIMER observers and synchronous
diagnostics in the qualified reference image; observational hooks remain separate.

Preparation/reclamation run in a preemptible kernel worker. The timer must not
acquire `BPF_MANAGER`, allocate, destroy artifacts, wait for readers or format
output. New management syscalls copy bounded requests/chunks, enqueue work or
read bounded status. Legacy BPF mutation calls reject while managed control is
active. Qualify the named reference image and management workload; arbitrary
legacy syscalls/userspace workloads are outside the timing claim. Do not perform
a general syscall-preemption rewrite.

### One requested motor pair per invocation

Add a managed helper that records a pair in invocation-local storage; success
means captured, not applied. A second request fails the whole invocation even
when its error is ignored. No request means the defined zero-output result.
Only successful completion allows ARM-A to evaluate the pair and the kernel to
submit one complete command. Interpreter, map, helper/request, admission-budget,
execution or queue failure discards the request and enters the stop path.

Keep legacy `MotorPairV1` semantics. Deny direct GPIO/PWM/motor helpers to managed
programs. At the shared actuator boundary reject competing ordinary BPF/userspace
commands to the managed wheel pair; trusted safety stop remains independent.

### Acknowledged safe handoff

1. Prepare/admit B while A runs.
2. At a release boundary finish A and select trusted safe mode.
3. Discard unsent A commands; finish any started frame without truncating it.
4. Send a prioritized `SafeBarrier`.
5. MCU clears pending motion and sends one atomic `(0,0)` FPGA transaction.
6. MCU reads coherent post-transaction status and verifies the accepted sequence.
7. MCU returns a correlated `SafeAck`.
8. Publish B at the next eligible 10 ms boundary and permit its fresh commands.

Reuse UART framing/CRC and FPGA transactions; add only required session and
correlation messages, without generic reliable RPC. Reverse MCU TX must own
bounded whole frames and handle backpressure; best-effort `ByteIo::write` cannot
prove acknowledgement delivery or prevent interleaving.

The operational timeout is 80 ms from entry into safe handoff, including
acknowledgement and commit. Timeout fails the operation, suppresses motion and
invokes the existing stop path. It does not prove remote outputs became safe at
that instant. Replacement never issues an e-stop release.

### Reset, discontinuity and stop

Reset/link discontinuity cancels handoff eligibility, clears command/barrier/ack
mailboxes and leaves outputs disarmed. Require link/FPGA requalification,
explicit operator rearm and a fresh activation/command afterward.

There is no qualified persistent boot ID. Use explicit session establishment and
a tested drain procedure, never timer-derived uniqueness. While both peers
prohibit motion, drain software queues, hardware FIFOs and decoder state; retain
at least 200 ms quiescence before establishing a new session. Qualify the actual
buffering/reset behavior so delayed acknowledgements cannot survive or authorize
rearm. The trusted point-to-point fault model does not claim cryptographic
protection from a malicious UART peer.

Stop before publication cancels replacement. Stop after publication leaves the
new installation committed but inhibited. Neither automatically resumes control.

## 5. Public interfaces, operator workflow and recorder

### Signed bundle and administration

Use a small canonical binary bundle: version and checked lengths; behavior ID,
revision and payload digest; fixed control slot; exact helper/context versions;
effect ceiling and private-array declaration; normalized instructions; full
signer identity and Ed25519 signature over domain-separated manifest and payload.
Reuse signing/hash implementations. Kernel verification and timing admission
compute cost; signed declared cost is not trusted. Independently reject multiple
legacy ELF entries, unsupported maps and ignored relocations before publication.

Keep `SYS_BPF` and add independently versioned request structures before the
legacy `BpfAttr` size check. The administration surface is limited to:

- Upload begin/chunk/finalize; operation and slot query.
- Activate with expected generation; rollback with expected generation and exact
  previous artifact; cancel pending operation; deactivate and retire.
- Recorder read/status.

Requests specify sizes, versions, reserved-zero fields and bounded lengths.
Distinguish malformed input, authentication, unsupported feature, stale identity,
busy operation, capacity exhaustion and failed handoff. Async requests return
operation IDs; query distinguishes preparation, handoff, commitment and failure.
Lost responses must permit querying rather than encourage blind re-execution.
No generic history database or fleet API.

Add `BEHAVIOR_ADMIN` to existing capabilities. Provision one dedicated installer;
ordinary init children receive none. Administration grants no direct actuation.
Runtime effects come from signed declarations constrained by trust policy and
the fixed slot ceiling.

Extend the CLI/signed loader along one physical path:
host CLI -> bounded framed debug UART -> installer -> versioned ABI -> worker.
Use nonblocking UART and stop-and-wait/credit transfer sized to qualified receive
capacity. Bulk allocation/verification never runs in receive or syscall critical
sections. Support upload, query, activate, rollback, stop/deactivate and audit
export. No networking, SSH, writable filesystem or general shell is necessary.
Acceptance uploads B after boot with B absent from the boot image.

### Bounded RAM recorder

Extend the existing decision vocabulary into one kernel-owned recorder allocated
before managed execution: 2,048 fixed records, at most 96 bytes each (192 KiB).
Record artifact registration/rejection and identity; preparation, handoff, commit,
rollback and retirement; cycle/generation-correlated requested/decided pairs;
local queue outcome, command sequence and sink acknowledgements; controller
faults, deadline misses, e-stop, link loss, watchdog, reset, recording loss and
export gaps.

Use monotonic ticks with export clock frequency/session identity. Keep the latest
authoritative stop summary separately. On the qualified CPU use a short bounded
IRQ-masked append, without per-core machinery. Overwrite oldest records on wrap
and increment explicit loss counters. Recording cannot block control or make
activation depend on log space. Export reports the retained interval and every
cursor gap. Suppress repeated unchanged stopped-state records. Distinguish policy
approval, local enqueue and sink acceptance; none proves motor movement.

Promise a retained window after normal stop, not lossless continuous UART export,
an entire 24-hour history, power-loss recovery or deterministic replay.

## 7. Acceptance and retained evidence

The authoritative machine-readable thresholds are
[v0.5-acceptance.json](../../performance/v0.5-acceptance.json). Reducers and generated
reports consume it; changing a threshold is a contract change, not a way to pass
a run. The initial host benchmark format is independent of the future UART and
recorder binary ABI. Its self-tests are synthetic evidence only; missing physical
checks remain blocked and cannot become a release pass.

### Software and model evidence

| Property | Required scenarios |
|---|---|
| Authentication/loading | Valid bundle; tamper every security-relevant field; malformed/truncated/oversized inputs; unsupported ELF publishes nothing |
| Preparation isolation | Allocation/verification/binding/admission injection preserves A's identity/state, previous artifact and active charge |
| Private state | B cannot access A; rollback zeroed; undeclared/global/stale handles reject |
| Ownership | Loader exit during upload, preparation, active operation and retirement obeys specified lifetimes |
| Publication | Concurrent writers, stale A→B→A, cancellation/stop/boundary races; one authoritative installation |
| Reclamation | At least 100,000 host lifecycle operations, high-water marks and retained-reference accounting; generation exhaustion and retirement-full states |
| Handoff | Every byte offset of old frames; no A command after accepted barrier; wrong/stale ack cannot commit B |
| Failure custody | Interpreter/map/helper/queue faults stop; observer failure cannot suppress managed control; failed invocation leaks no request |
| Scheduling | Fake-clock absolute deadlines, explicit missed releases, no catch-up; unsupported long legacy syscall cannot produce false timing pass |
| Recorder | Wrap/overflow/stale cursor/interrupted export/malformed records/missing identity produce errors or explicit gaps while control continues |
| ABI | Legacy compatibility outside managed restrictions; unknown versions, sizes and reserved fields reject predictably |

Run `scripts/verify/engineering-audit.sh --quick` during integration and `--full`
on the release candidate, plus relevant firmware simulation, RTL, Miri and
concurrency models. Extend existing suites; do not introduce a test framework.

### Timing contract

Freeze the embedded period at 10 ms and retain the 50% modeled BPF utilization
ceiling. Recalibrate the shipped interpreter and permitted managed helpers,
including state access, request handling and recorder overhead. Remove
JIT-derived managed admission descriptions.

Require no unaccounted releases or ordinary-workload deadline misses; completion
strictly before scheduled release plus 10 ms; publication/entry at the next
eligible release after sink-safe readiness; operational handoff within 80 ms;
and the 5% paired p99 recorder target. For matched same-image trials use
`p99_on <= 1.05 * p99_off`, nearest-rank quantiles, and report paired absolute
deltas and observed maxima. Do not silently import the older draft's additional
confidence-bound gate. Never hide cold starts, rejected requests, timeouts or
failed updates. These are measured qualification and model-based admission,
not a mathematical hardware WCET proof.

### Physical electronics campaign

Use qualified Pi5 + operational RP2040 + programmed FPGA with motors disconnected:

- Three attributable cold boots; each boot passes independently before pooling.
- Post-boot upload of an absent signed controller; valid replacement, invalid
  signature, verifier rejection, over-budget rejection and manual rollback.
- At least 10,000 successful activation/rollback transitions across boots,
  at least 1,000 per boot, covering phase across the 10 ms period.
- At least one million releases including upload, preparation, rollback and
  recorder pressure. Count scheduled safe-mode cycles explicitly.
- Simultaneously capture both final PWM outputs and directions through handoff.
- Inject stop, link loss, MCU reset and acknowledgement failure in preparation,
  handoff and after commitment; repeat every fault/phase combination five times.
- A one-hour v0.5 pilot followed by one continuous 24-hour unloaded
  runtime-evolution soak using the qualified acquisition procedure.

Missing releases, unexplained safe transitions, stale outputs and unplanned
resets invalidate the relevant claim. Retain failed runs. The bounded runtime
recorder is not the independent continuous physical acquisition system.

Retain source/features, toolchain, kernel/rootfs/MCU/FPGA hashes, signed bundles,
wiring, instrument configuration/uncertainty, raw evidence, reduction commands
and results. Reject missing/truncated/reordered evidence and reproduce canonical
results from retained inputs. Rebuild the recorded candidate under its recorded
reproducibility conditions and compare hashes. Motor current/heating, mechanical
stopping distance and assembled-car reliability require later powered gates.

## 8. Deliberate cuts and immediate work

Exclude general multi-slot/multi-hook transactions, general ELF maps/shared
writable state/migration, automatic rollback/persistent anti-rollback, global
asynchronous RCU redesign, SMP/core partitioning/Linux coexistence, JIT/interpreter
micro-optimization/generic HAL expansion, persistent recorder/replay/fleet
services and paper-specific experiment matrices.

The first engineering moves are baseline/contract reconciliation; atomic
MCU/FPGA sink and reset software/model checks; bounded asynchronous preparation;
artifact/instance ownership and retirement with churn tests before activation;
then the absolute managed slot followed by acknowledged handoff and rollback.

Deferred physical M1 inputs are continuity and clock calibration, authoritative
configuration/READY/SPI timing and handoff, remaining hold/pulse/interface
qualification and programming provenance. Bitstream generation, setup timing
and digital pin-assignment checks are complete on the recorded FPGA branch;
they do not close these physical requirements. These inputs no longer block
software implementation. Preserve deployment/runtime guards until their
respective bench prerequisites are qualified; hardware actuation remains
disabled during software development. Host simulations cannot substitute for
physical qualification or justify relaxing the acceptance thresholds.

v0.5 is complete only when live upload → prepare → confirmed safe handoff →
activate → fresh-state rollback → inspect works on qualified electronics within
the declared timing and resource bounds.
